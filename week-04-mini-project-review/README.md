# Week 4: Mini Project Share Out and Retrospective

Format: Presentations plus a structured retro. Length: about 75 minutes. Slides: slides/week-04-slides.pptx

No new content this week. This is the payoff for weeks 2 and 3, and it sets the template for every review week that follows, weeks 8 and 12.

## What members should have coming in

Each group, working since week 3, should have their own question on nps_units.csv, or something close to it. At least one engineered column that did not exist in the raw data. A short Excel analysis and a Tableau dashboard. A one line claim, not just a chart.

Full spec is in mini-project-brief.md. Rubric is in rubric.md. Send both at the end of week 3, not the start of week 4. Groups need the time in between to actually build something.

## 1. Share out, about 30 minutes

Four to five minutes per group. Dashboard on screen. Claim stated in the first 30 seconds so it never gets buried at the end. One or two questions per group from the room. Say up front that this is not a competition. The point is seeing five or six different approaches to the same dataset.

## 2. Retrospective, about 20 minutes

Whole branch discussion, not per group reports. Three prompts, in order. What felt hard this cycle. What is one thing that clicked. What do members want more practice on before SQL starts.

Officers should actually write these down. This is real input for pacing the SQL block, not a formality.

## 3. Wrap up, about 10 minutes

Month one was about getting comfortable enough with the tools to ask a real question and defend it. Month two is SQL. Same instinct, a different way into the data, and it is the single most requested skill in analyst job postings.
