# Curriculum Philosophy

Analytical thinking is the actual subject. SQL, Python, Excel, and Tableau are how members practice it.

## Three decisions

**Skills are taught in blocks, but used together.** A dedicated Excel week teaches Excel; a dedicated SQL week teaches SQL. But once a skill is introduced, projects keep using it alongside whatever's new — nothing gets taught once and dropped. Research on skill retention backs this up: practicing skills in isolation feels easier short-term, but mixing them produces better long-term retention and better judgment about which tool fits a question. Total beginners still need the isolated lesson first — pure mixing from day one doesn't work either.

**Real, messy data. No Titanic, no Iris.** Every dataset should have genuine data-quality issues worth noticing, and be rich enough that two groups can each find a different, defensible insight. If a dataset only supports one "correct" finding, it's teaching syntax, not analysis.

**Themes rotate, skills don't reset.** Each project cycle uses a different domain. Partly for variety — but mainly because when every team works from an identical prompt, portfolios end up looking interchangeable. A rotating theme means members are more likely to land on a question they actually care about.

## In a session

- State the question before the formula. Never introduce syntax without the question it answers.
- When a group asks "is this right," ask what they were trying to find out before you answer the syntax question.
- Push different groups toward different questions rather than one "intended" answer.
- Name data-quality issues out loud when they come up. Noticing them is the skill.
