# Curriculum Philosophy

Analytical thinking is the actual subject. SQL, Python, Excel, and Tableau are how members practice it.

## Three decisions

Skills are taught in blocks, but used together. A dedicated Excel week teaches Excel. A dedicated SQL week teaches SQL. Once a skill is introduced, projects keep using it alongside whatever is new. Research on skill retention backs this up. Practicing a skill in isolation feels easier in the short term, but mixing skills together produces better long term retention and better judgment about which tool fits a given question. Total beginners still need the isolated lesson first. Mixing everything together from day one does not work either.

Real, messy data, every time. No Titanic, no Iris. Every dataset should have genuine quality issues worth noticing, and should be rich enough that two different groups can each find a different, defensible insight. If a dataset only supports one correct finding, it is teaching syntax, not analysis.

Themes rotate, skills do not reset. Each project cycle uses a different domain. This is partly for variety, but mostly because when every team works from an identical prompt, portfolios end up looking interchangeable. A rotating theme means members are more likely to land on a question they actually care about.

## In a session

State the question before the formula. Never introduce syntax without the question it answers.

When a group asks if something is right, ask what they were trying to find out before you answer the syntax question.

Push different groups toward different questions rather than steering everyone toward one intended answer.

Name data quality issues out loud when they come up. Noticing them is the skill.
