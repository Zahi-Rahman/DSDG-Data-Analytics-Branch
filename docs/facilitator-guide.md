# Facilitator Guide

For officers running a session from this repo.

## Before the session

Read that week's README once, at least a day ahead.

Do the main exercise yourself. If a step confuses you with the answer key in hand, it will be worse for a first timer.

Bring a laptop with everything pre-installed. Do not debug installs live if you can help it.

## Running the room

Groups of 3 to 4. Bigger and someone checks out. Smaller and a stuck group has no one to unstick them.

Check every group in the first 10 minutes to catch setup problems early, then step back.

When a group asks if something is right, ask what they were trying to find out before you answer.

Protect the last 10 minutes for wrap up. It is what turns a set of separate sessions into a program.

## Early finishers versus stuck groups

Early finishers: point them at a second, harder question on the same dataset, ideally one that needs a technique they have not used yet.

Stuck groups: narrow the question, do not hand over the answer. Asking "what is one thing you know for sure from this data" usually gets them moving again.

## Running a review week, weeks 4, 8, and 12

Two segments, kept separate.

Share out, about 20 to 25 minutes. Each group shows one finding in about 5 minutes. The audience is the rest of the branch. This is exposure to different approaches, not a ranking.

Retrospective, about 15 minutes. As a full group, not per team: what felt hard, what would help, what clicked. Officers should actually write this down. It is real input for pacing.

## One thing to watch for

If every group lands on the same insight, the prompt was too narrow. That is not a sign the groups did anything wrong.
