# Facilitator Guide

For officers running a session from this repo.

## Before the session
- Read that week's README once, at least a day ahead.
- Do the main exercise yourself. If it's confusing to you with the answer key in hand, it'll be worse for a first-timer.
- Bring a laptop with everything pre-installed. Don't debug installs live.

## Running the room
- Groups of 3–4. Bigger and someone checks out; smaller and a stuck group has no one to unstick them.
- Check every group in the first 10 minutes to catch setup problems early, then step back.
- When a group asks "is this right," ask what they were trying to find out before you answer.
- Protect the last 10 minutes for wrap-up. It's what turns separate sessions into a program.

## Early finishers vs. stuck groups
- Early finishers: point them at a second, harder question on the same dataset — ideally one needing a technique they haven't used yet.
- Stuck groups: narrow the question, don't hand over the answer. "What's one thing you know for sure from this data" usually unsticks it.

## Running a review week (weeks 4, 8, 12)
Two segments, kept separate:
1. **Share-out (~20–25 min).** Each group shows one finding in ~5 minutes. Audience is the rest of the branch — this is exposure to different approaches, not a ranking.
2. **Retrospective (~15 min).** As a full group, not per-team: what felt hard, what would help, what clicked. Officers should actually write this down — it's real input for pacing.

## One thing to watch for
If every group lands on the same insight, the prompt was too narrow — not a sign the groups did anything wrong.
