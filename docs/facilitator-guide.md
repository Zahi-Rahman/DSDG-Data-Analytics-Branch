# Facilitator Guide

For officers leading a Data Analytics branch session for the first time.

## Before the session
- Read that week's `README.md` fully once, at least a day ahead — it's written as a script with timing, but you should know where it's going before you're running it live.
- Open the slides and the dataset yourself and actually do the main exercise. If a step is confusing to you as a facilitator with the answer key in hand, it will be worse for a first-time member.
- Bring a laptop with everything pre-installed/pre-loaded — don't debug software installs live if you can avoid it.

## Running the room
- **Groups of 3–4.** Bigger and someone disengages; smaller and a stuck group has no one to unstick them.
- **Float, don't hover.** Check every group within the first 10 minutes of any hands-on block to catch setup problems early, then let groups work without you standing over them.
- **When a group asks "is this right," answer with a question first** — "what were you trying to find out?" — before you answer with a fix. The goal is judgment, not a correct-looking chart.
- **Protect the last 10 minutes.** It's tempting to let a good working session run long, but the wrap-up (what we learned, what's next week) is what makes the sequence of sessions feel like a program instead of a series of unrelated meetings.

## Groups that finish early vs. groups that are stuck
- **Early finishers:** point them at a second question on the same dataset, ideally one that requires a technique they haven't used yet this session. Don't let them idle or start helping other groups unless they want to — better they go deeper.
- **Stuck groups:** narrow the question, don't hand over the answer. "What's one thing you know for sure from this data" is usually enough to get unstuck.

## Running a review week (weeks 4, 8, 12)
Two distinct segments — don't blend them:
1. **Share-out (~20–25 min):** each group gets ~4–5 minutes to show one finding and how they got it. Audience is the rest of the branch, not a formal panel. The goal is exposure to different approaches, not ranking teams.
2. **Retrospective (~15 min):** as a full group, not per-team — what felt hard this cycle, what would you want more practice on, what's one thing that clicked. Officers should actually take notes here; it's real input for adjusting the next cycle's pacing.

## A note on tone
The dataset should feel like a genuine puzzle, not a test with one right answer. If a session ends with every group having found the *same* insight, that's a sign the prompt was too narrow next time — not that the groups did anything wrong.
